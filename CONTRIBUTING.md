# Contributing to pymetadata

Contributions are welcome, be it bug reports, documentation or code.

- **Questions and bugs** belong in the [issue tracker](https://github.com/matthiaskoenig/pymetadata/issues).
- **Code** comes in as a pull request against `develop`, the default branch;
  `main` only tracks the latest release. Fork the repository, branch off
  `develop`, and open the pull request from your branch.
- Every pull request runs the tests (linux, macos and windows, python 3.11 to
  3.14), `ruff` and `ty`, and the documentation build. All of them have to pass
  before a merge is possible.
- A pull request from outside needs a review and approval by
  [@matthiaskoenig](https://github.com/matthiaskoenig).

The development setup, the test, lint and type commands, the branch model and
the release process are described in the
[development documentation](https://matthiaskoenig.github.io/pymetadata/development/),
i.e., `docs/development.md` in this repository.
